# 랜덤 반복 주기 설계

## 의도

사용자는 키를 누르는 방식과 누름 지속 시간은 그대로 유지하면서, 각 반복의 주기를 최소~최대 초 범위에서 무작위로 정하고자 한다. 예: `5~10초`.

## 목표

- 앱에서 반복 주기의 최소값과 최대값을 초 단위로 각각 입력한다.
- ESP32는 첫 입력을 즉시 수행한 뒤, 매번 다음 입력까지의 주기를 범위 내에서 새로 무작위 선택한다.
- 미연결 시뮬레이션도 동일한 방식으로 횟수를 계산한다.
- 설정 미리보기의 예상 횟수는 범위의 평균 주기를 기준으로 표시한다.

## 제외 범위

- 키 누름 시간과 서보 각도·동작 방식 변경
- 기존 `START total interval hold` 시리얼 명령의 형식 변경

## 접근 방식

1. 앱만 랜덤화: 실제 연결 기기의 간격이 고정되는 문제가 있어 제외했다.
2. 앱과 펌웨어 확장: BLE `START` 명령에 `intervalMinSec` 및 `intervalMaxSec`를 추가하고, 펌웨어가 주기를 결정한다. 이 방식을 선택했다. 기존 `intervalSec`만 전송하는 이전 앱과의 호환을 위해 펌웨어는 최소·최대값이 없으면 기존 고정 간격을 사용한다.

## 구현 개요

- Flutter: 기존 단일 반복 주기 입력칸을 `최소 반복 주기 (초)`, `최대 반복 주기 (초)` 두 칸으로 교체한다. 값이 잘못되었거나 최대값이 최소값보다 작으면 시작하지 않고 안내한다. BLE 명령에는 최소/최대 값을 보낸다.
- ESP32: 설정에 최소·최대 주기를 저장한다. 매 입력이 끝난 후 다음 전체 주기를 난수로 정하고, 현재 FSM의 누름·복귀 시간을 제외한 대기 시간만 기다린다. 난수는 부팅 시 시드한다.
- 표시: 예상 횟수와 시뮬레이션은 평균 주기 `(최소 + 최대) / 2`에 기반한다.

## 검증

- Flutter 설정 모델 단위 테스트: 평균 기반 예상 횟수, 유효 범위 판정.
- 펌웨어: PlatformIO 빌드 확인. 하드웨어에서 BLE 시작 명령 후 직전·다음 타건 간격이 범위 안에 들어가는지 시리얼 로그로 확인한다.
